# Local Formula OCR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. Steps use checkbox tracking.

**Goal:** Deliver a local Windows formula OCR application with user-selectable CPU/CUDA and a dedicated conda development environment.
**Architecture:** PySide6 UI owns interaction; one spawned worker owns Transformers model lifetime. SQLite owns history/settings; bundled browser math assets own preview and image rendering.
**Tech Stack:** Python 3.12/conda img2tex, PySide6, Transformers 5.17, PyTorch 2.14, Pillow, SQLite, KaTeX/MathJax.
**Spec:** docs/superpowers/specs/2026-11-02-local-ocr-design.md

## Global Constraints
Use conda img2tex only; CPU remains selectable without CUDA; user device selection is explicit; all daily operations local; preserve raw/model/editor values separately; no modifications to analysis or SimpleTex.

User amendment: external screenshot/image copying, no built-in screenshot or global shortcuts. Ctrl+V pastes images only inside this app window; keep normal Ctrl+C text copy and editor text paste.

## Review Focus
1. CUDA unavailable or out of memory must not prevent launching/editing on CPU.
2. Cancel/reload/late responses must not save or overwrite another task.
3. Alpha/EXIF/large and empty input must preserve valid pixels and show actionable errors.
4. Editable math exports must preserve fractions/matrices and reject unsupported constructs explicitly.
5. Packaging, non-ASCII paths, offline assets and history restoration must work outside source cwd.
